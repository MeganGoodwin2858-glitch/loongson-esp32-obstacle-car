# 团队协作约定

## 开始修改

1. 克隆仓库，阅读 `README.md`、`CHANGELOG.md` 和 `TODO.md`。
2. 使用描述任务的分支名，围绕一项可验收修改提交。
3. 修改配置时保留根目录本机 `sdkconfig`，将需要共享的选项整理到 `config/sdkconfig.car` 或相应默认配置，并说明原因。
4. 修改 `phone/wifi.html` 后重新生成 `main/web_server/remote_page.h`。
5. 运行与修改相关的既有测试，记录测试命令、结果和跳过项目。

## 提交内容

提交应用源码、可编辑页面、协议、必要资源、锁文件和文档。编译缓存、工具链安装、设备私有数据和恢复备份按 `.gitignore` 分开管理。

涉及 GPIO、接线、帧格式、会话或停车行为时，同时更新对应文档和已有回归用例。跨板协议变更需要说明 ESP32 与龙芯客户端的兼容版本。

## 评审记录

每次合并说明改动目的、涉及模块、测试结果、硬件状态和待办。硬件结论附日期、板型、固件哈希或提交号、接线、具体动作、观测时长与结果。

仓库负责人在 GitHub 设置中邀请组员为 Collaborators，按团队需要授予权限。成员名单待补。

## 版本进度

当前恢复快照使用 `recovered-2026-11-06` 作为文档标识。固件 `PROJECT_VER=2.1.0` 延续上传项目。团队确认实车验收后，再确定自己的发布编号和发布包内容。
