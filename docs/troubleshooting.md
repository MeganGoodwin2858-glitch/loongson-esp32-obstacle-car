# 故障排查

先保存现象、源码提交、配置和日志，再定位对应环节。下面的判断依据恢复源码，硬件结论仍需要现场测量。

## 网页能打开，车轮没有动作

浏览器打开设备当前 IP 下的 `/api/remote/status`，记录返回内容。该 GET 用于查询状态。

| 字段 | 需要检查的内容 |
| --- | --- |
| `ready` | 为 false 时检查启动日志、电机 PWM 初始化与硬件故障标记 |
| `armed` | 为 false 时，在网页上完成本次使能，再操作摇杆 |
| `estop` | 为 true 时先查明急停原因，解除后重新使能 |
| `ble` | 为 true 时 BLE 拥有控制连接，网页使能可能被拒绝 |
| `web` | 表示网页当前拥有控制会话，其他页面持有会话时需要等待其停车 |
| `mode` | 0 为手机手动，1 为龙芯自动，2 为原功能 |
| `left`、`right` | 表示软件输出百分比，需结合轮向、驱动供电与电气测量判断实际动作 |

页面默认速度上限为 40%。松手、切后台或停车会撤销使能，下一次操作需要重新使能。命令序号、会话、急停与硬件条件共同决定请求是否被接受。

| HTTP 结果 | 排查方向 |
| --- | --- |
| 400 | 检查 `X-Car-Control: 1`、请求体长度和入口，控制帧应为 20 字节 |
| 409 | 检查 `ready`、控制权、模式、急停、会话与命令序号 |
| 410 | 正在使用历史动作入口，重新加载设备根路径 `/` 的 Wi-Fi 页面 |

如果修改过 `phone/wifi.html`，运行 `python tools/embed_wifi_page.py` 后重新构建，核对设备运行的固件版本。

## 龙芯串口预检失败或收不到有效帧

1. 使用先锋派 Linux 运行 `--preflight --port /dev/ttyS2`，记录退出码和 JSON 中的 `errors`。
2. 核对设备名为 `ttyS2`、寄存器地址包含 `0x16100800`，并核对设备树 `serial2` 别名。
3. 根据预检信息检查控制台/getty 占用与字符设备身份。
4. 对照接线表检查 IO8 → J8 物理 10、IO9 ← J8 物理 8，以及两板共地。
5. 核对 115200、8N1、3.3V TTL 和当前固件 UART 配置。

历史上 IO18 曾被误接成 IO8，OLED 也曾与 UART 接线混淆。按 [接线说明](wiring.md)核对实际丝印。

若日志只有全零、BREAK、CRC 或组帧错误，记录固定时长内的原始字节数和错误数量，再检查连线、电平与信号波形。自动客户端收到解析错误后会终止当前控制，需要人工处理后重新启动。

## 有测距帧，自动模式仍无法使能

检查状态是否同时满足 `mode=1`、BLE 在线、UART-ready、急停已清除，以及有效的 `auto_session`。客户端还要求同一会话连续三个新的有效测距，再发送 ARM 并等待新状态确认。

监视模式使用默认命令。启动运动时，现场确认后同时提供 `--enable-motion --wiring-confirmed`。已使能的会话会被客户端拒绝接管，需要人工重新选择自动模式。

重复的 `sample_seq` 可以出现在连续遥测中，因为遥测周期为 50ms，而采样周期至少为 80ms。重复帧不会增加准备/清路计数。主机按接收时刻与 `age_ms` 计算时效，超过 180ms 的测距会失效，状态断流阈值为 150ms。

## 测距无效或数值异常

| `result` | 含义与检查方向 |
| --- | --- |
| 0 | 有效，继续核对距离、采样序号和时效 |
| 1 | 无回波或超时，检查目标、模块接线、供电与回波 |
| 2 | 超范围，核对模块工作范围与实际目标距离 |
| 3 | 噪声、多脉冲或驱动错误，检查波形与日志 |
| 4 | 传感器关闭，检查当前构建配置 |
| 5 | 采样过期，检查采样和处理时序 |

当前软件接受 20..4000mm。ECHO 使用降压后信号接 IO11，TRIG 接 IO10。使用多个已知距离目标记录原始 Echo 脉宽与输出距离，校准结果填入 [测试记录](test-record.md)。

## OLED 黑屏

当前配置为 SSD1306 128×64、地址 `0x3C`、SDA41、SCL42、400kHz。先核对模块正反面型号与四针丝印，再测屏幕端 VCC/GND 电压，并检查接线和 I²C 波形。

2026-11-05 记录中初始化日志正常，但用户观察仍黑屏。排查结果需要附上可见显示证据。

## 构建或桌面测试失败

| 现象 | 处理方向 |
| --- | --- |
| 板型、Flash 模式或屏幕选项错误 | 核对 `config/sdkconfig.car` 与生成的 `sdkconfig` |
| 缺少托管组件 | 核对锁文件与 `managed_components/`，联网恢复或解压离线包 |
| 找不到 `cl` | 使用 Visual Studio x64 开发终端 |
| 找不到 cJSON | 检查 `IDF_PATH` 和 `components/json/cJSON` |
| Python 有 7 项跳过 | 编译固件核心模拟器并设置 `CAR_FIRMWARE_SIMULATOR`，或运行完整回归脚本 |
| Linux 串口程序在 Windows 退出 | 在先锋派 Linux 执行串口入口，电脑上运行协议与状态机测试 |

保留第一条错误及其上下文、实际执行命令、工具版本和退出码，便于组员复现。
