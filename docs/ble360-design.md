## 实施选择
沿用 ESP-IDF 5.5.4、qebabe-xiaoche、原 GPIO12/13/14/21 和语音/显示/网络代码。
使用 IDF 自带 NimBLE GATT，无新增在线库。独立、可在电脑编译的控制核心负责摇杆混控、协议、模式、超时、急停、旧动作队列。
固件服务在一把互斥锁内处理命令、状态和 PWM，避免旧任务覆盖新命令。
手机提供本地 HTML 虚拟手柄，经 Web Bluetooth 直连（Android Chromium；iOS 需支持 Web Bluetooth 的浏览器容器，Safari 不支持）。
与只用第三方 BLE 调试软件相比，交付实际摇杆界面；与重写全部小智应用相比，保留原功能并收敛电机输出。

## 固定规则
- 360° 是连续差速转向，不提供两轮底盘不具备的横向平移。
- x/y 范围 -1000..1000，x 右为正、y 前为正；径向死区 12%，连续重映射；左右输出 y+x / y-x，归一化到速度上限。
- 开机手动停车，需显式使能；默认速度 40%。BLE DRIVE 必须每 100ms 以内刷新；300ms 无有效运动帧停车并取消使能。
- 松手 STOP、断连、模式切换、错误帧、急停都停车并清动作队列。急停锁存，解除仍停车，须再次使能。
- 手动、龙芯自动、原功能三个独占模式。原有网页/MCP/情绪动作在“原功能”模式使能后可用；遥控和自动模式禁止其驱动车轮，语音和显示仍可用。
- 龙芯端不在上传源码内。提供带 CRC16、会话、序号的 UART 接收与主机示例；引脚尚未确认，默认不启用 UART，不能声称已完成实车避障。
- 输出换向先将四路 PWM 置零，再写新方向；取消原异步 fade 和过期延时停车任务。PWM 初始化或写入失败锁存急停，禁止退化为全速 GPIO。
- BLE 最多一名控制者，断连不自动还原旧动作；会话轮换阻断停止、模式切换前缓存的旧运动帧。
